Configuring the Cache

HeFQUIN supports a two-level cache with an in-memory L1 cache and a persistent L2 cache. The cache is configured as part of the FederationAccessManager.

Example Configuration

[] a ec:HeFQUINEngineConfiguration ;
   ec:fedAccessMgr [
       a ec:FederationAccessManager ;
       ec:javaClassName "se.liu.ida.hefquin.federation.access.impl.FederationAccessManagerWithHierarchicalCache" ;
       ec:constructorArguments (
           [ ec:argumentTypeName "se.liu.ida.hefquin.federation.access.FederationAccessManager" ;
             ec:javaClassName "se.liu.ida.hefquin.federation.access.impl.AsyncFederationAccessManagerImpl" ;
             ec:constructorArguments ( ec:value:ExecServiceForFedAccess ) ]

           # L1 cache
           <L1 cache configuration>

           # L2 cache
           <L2 cache configuration>
       )
   ] .

The L1 and L2 cache configurations are passed as the second and third constructor arguments of FederationAccessManagerWithHierarchicalCache, respectively. 

# L1 cache
[ ec:argumentTypeName "se.liu.ida.hefquin.base.datastructures.Cache" ;
    ec:javaClassName "se.liu.ida.hefquin.federation.access.impl.cache.CacheLayer" ;
    ec:constructorArguments (
        [ ec:argumentTypeName "java.util.Map" ;
          ec:javaClassName "java.util.HashMap" ;
          ec:constructorArguments () ]
        100
        [ ec:argumentTypeName "se.liu.ida.hefquin.base.datastructures.impl.cache.CachePolicies" ;
          ec:javaClassName "se.liu.ida.hefquin.federation.access.impl.FederationAccessManagerWithHierarchicalCache$DefaultHierarchicalMapCachePolicies" ;
          ec:constructorArguments ( 300 ) ]
    )
]

In the example, the L1 cache uses CacheLayer. Its first constructor argument specifies the Map implementation used internally, in this case an in-memory HashMap. The second argument specifies the maximum number of elements (100). The third argument is a CachePolicies instance whose constructor argument specifies the time-to-live (TTL) in seconds (300). 

# L2 cache
[ ec:argumentTypeName "se.liu.ida.hefquin.base.datastructures.Cache" ;
  ec:javaClassName "se.liu.ida.hefquin.federation.access.impl.cache.mapdb.MapDBCache" ;
  ec:constructorArguments (
      1000
      [ ec:argumentTypeName "se.liu.ida.hefquin.base.datastructures.impl.cache.CachePolicies" ;
        ec:javaClassName "se.liu.ida.hefquin.federation.access.impl.FederationAccessManagerWithHierarchicalCache$DefaultHierarchicalMapCachePolicies" ;
        ec:constructorArguments ( 600 ) ]
  )
]

In the example, the L2 cache uses MapDBCache. Its first constructor argument specifies the maximum number of elements (1000). The second argument is a CachePolicies instance whose constructor argument specifies the TTL in seconds (600).

Both MapDBCache and the ChronicleMap-based implementation can be used as the L2 cache. MapDBCache provides faster startup when running the regular CLI, where JVM startup time has a greater impact. When HeFQUIN is run as a service, this difference in JVM startup time is not relevant.
