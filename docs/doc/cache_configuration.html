Overview

HeFQUIN supports caching of responses from federation members. By default, HeFQUIN uses a two-level cache consisting of an in-memory L1 cache and a persistent L2 cache. The L1 cache provides fast access within an engine instance, while the L2 cache persists cached responses across engine instances and across JVM restarts.

When HeFQUIN needs to issue a data retrieval or some other kind of request to a federation member, it first checks the L1 cache. If a matching non-expired response is found, it is returned directly without contacting the federation member. If no such response is found in the L1 cache, HeFQUIN checks the L2 cache. If a matching non-expired response is found there, it is returned and also added to the L1 cache. If neither cache contains a usable response, the request is issued to the federation member, and the response is stored in the caches for subsequent accesses.

If the cache reaches its configured capacity, an existing cache entry is removed according to the configured cache policy to make room for the new entry. Currently, the default cache policy uses least recently used (LRU) eviction.

Configuration

The L1 and L2 cache configurations are passed as the second and third constructor arguments of FederationAccessManagerWithHierarchicalCache, respectively.

Example Configuration

[] a ec:HeFQUINEngineConfiguration ;
   ec:fedAccessMgr [
       a ec:FederationAccessManager ;
       ec:javaClassName "se.liu.ida.hefquin.federation.access.impl.FederationAccessManagerWithHierarchicalCache" ;
       ec:constructorArguments (
           [ ec:argumentTypeName "se.liu.ida.hefquin.federation.access.FederationAccessManager" ;
             ec:javaClassName "se.liu.ida.hefquin.federation.access.impl.AsyncFederationAccessManagerImpl" ;
             ec:constructorArguments ( ec:value:ExecServiceForFedAccess ) ]

           # L1 cache
           _:b1

           # L2 cache
           _:b2
       )
   ] .

In the following example, the L1 cache is implemented based on HashMap. The first constructor argument specifies the Map implementation used internally, the second specifies the maximum number of cache entries that can be stored at the same time (set to 100 in the example), and the third defines the CachePolicies instance, whose constructor argument specifies how long each cache entry is retained before it expires, i.e., the time to live (TTL) in seconds (set to 300 seconds in the example). 

# L1 cache
_:b1 ec:argumentTypeName "se.liu.ida.hefquin.base.datastructures.Cache" ;
     ec:javaClassName "se.liu.ida.hefquin.federation.access.impl.cache.CacheLayer" ;
     ec:constructorArguments (
         [ ec:argumentTypeName "java.util.Map" ;
           ec:javaClassName "java.util.HashMap" ;
           ec:constructorArguments () ]
         100   # cache capacity (i.e., max number of cache elements)
         [ ec:argumentTypeName "se.liu.ida.hefquin.base.datastructures.impl.cache.CachePolicies" ;
           ec:javaClassName "se.liu.ida.hefquin.federation.access.impl.FederationAccessManagerWithHierarchicalCache$DefaultHierarchicalMapCachePolicies" ;
           ec:constructorArguments ( 300 ) ]   # time to live (TTL) in seconds
     ) .

In the example, the L2 cache uses MapDBCache. Its first constructor argument specifies the maximum number of cache entries that can be stored at the same time (set to 1000 in the example), while the second is a CachePolicies instance whose constructor argument specifies how long each cache entry is retained before it expires (set to 600 seconds in the example). 

# L2 cache
_:b2 ec:argumentTypeName "se.liu.ida.hefquin.base.datastructures.Cache" ;
     ec:javaClassName "se.liu.ida.hefquin.federation.access.impl.cache.mapdb.MapDBCache" ;
     ec:constructorArguments (
         1000
         [ ec:argumentTypeName "se.liu.ida.hefquin.base.datastructures.impl.cache.CachePolicies" ;
           ec:javaClassName "se.liu.ida.hefquin.federation.access.impl.FederationAccessManagerWithHierarchicalCache$DefaultHierarchicalMapCachePolicies" ;
           ec:constructorArguments ( 600 ) ]   # TTL in seconds
     ) .

As an alternative to MapDBCache, ChronicleMapCache can be used as the L2 cache. MapDBCache provides faster startup when running the regular CLI, where JVM startup time has a greater impact. When HeFQUIN is run as a service, this difference in JVM startup time is not relevant, and ChronicleMapCache is likely to perform better for high-throughput workloads.
